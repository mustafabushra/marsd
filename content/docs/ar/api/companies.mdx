<Callout type="warning" title="لا نقطة نهاية للشركات تحت /api">
قراءة الشركات **لا تمرّ** بدالّة خادم. تجري من العميل مباشرةً إلى Supabase،
والتصريح فيها بسياسات RLS.
</Callout>

## لماذا هذا التصميم

دالّة خادم تقف بين العميل والقاعدة تحتاج أن تُعيد كتابة كل قاعدة تصريح قائمة:
من يقرأ أي شركة، وأي حقل يُخفى عن من. ونسخةٌ ثانية من تلك القواعد تفترق عن
الأولى عند أوّل تعديل.

فالتصريح في موضع واحد — سياسات القاعدة — والعميل يستعلم مباشرةً بتوكن Clerk
الذي يجعل `auth.jwt() ->> 'sub'` قابلاً للمقارنة فيها.

## كيف تُقرأ فعلاً

```js
import { getSupabase } from '@/lib/api'

const { data, error } = await getSupabase()
  .from('companies')
  .select('id, name, cr_number, city, sector, status, trust_scores(score, band)')
  .ilike('name', '%الفهد%')
  .limit(20)
```

RLS تُطبَّق على هذا الاستعلام: ما لا يُصرَّح لك بقراءته لا يعود، **بلا خطأ** —
صفوفٌ أقلّ لا رسالة رفض.

<Callout type="tip" title="وهذا يستحقّ انتباهاً عند التصحيح">
استعلامٌ يُرجع صفراً قد يعني «لا نتائج» أو «لا تصريح». والتمييز بينهما بفحص
الهويّة لا بقراءة الخطأ — فلا خطأ.
</Callout>

## ما هو متاح للقراءة

| الجدول | من يقرأ |
|---|---|
| `companies` | الجميع — السجل عامّ |
| `trust_scores` | الجميع |
| `company_documents` | مسؤول أو مراجع · أو مستأجر صاحبها |
| `reports` | مستأجر كاتبها · أو مراجع |
| `watchlist_items` | صاحبها وحده |

## ما ليس موجوداً

- **لا `GET /api/companies`** ولا أي نقطة REST للشركات
- **لا مفاتيح API** — راجع [مصادقة الواجهة](/docs/api/authentication)
- **لا ترقيم صفحات من الخادم** — يُستعمل `range()` من عميل Supabase
