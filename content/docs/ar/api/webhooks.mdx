<Callout type="danger" title="Webhooks غير منفَّذة">
لا يُرسل مرصد أحداثاً إلى أنظمة خارجية. لا تسجيل نقاط استقبال، ولا توقيع
حمولات، ولا إعادة محاولة.
</Callout>

هذه الصفحة موجودة لأن القسم مُدرَج في الشجرة — وتقول ما هو صحيح بدل أن تصف
واجهةً لا وجود لها.

## ما يقوم مقامها اليوم

**داخل المنتج:** جدول `notifications` والاشتراك اللحظي عليه عبر Supabase
Realtime. فما يظهر في جرس الإشعارات يصل بلا استطلاع.

```js
getSupabase()
  .channel('notifications')
  .on('postgres_changes',
      { event: 'INSERT', schema: 'public', table: 'notifications' },
      (payload) => { /* … */ })
  .subscribe()
```

**خارج المنتج:** لا شيء. ومن يحتاج إعلاماً في نظامه يستطيع اليوم أن يستعلم
دورياً عن الجداول التي يُصرَّح له بقراءتها — وهو استطلاع لا دفع.

## ما يلزم لو نُفِّذت

يُذكر كي يكون حجم العمل مرئياً، لا كوعد:

| المطلوب | لماذا |
|---|---|
| جدول نقاط الاستقبال | العنوان والأحداث المشترَك فيها ومفتاح التوقيع |
| توقيع الحمولة (HMAC) | المستقبِل يحتاج أن يتأكّد أن مرصد أرسلها |
| طابع زمني ومنع الإعادة | حمولةٌ مُلتقَطة لا يجوز أن تُقبل مرّة ثانية |
| إعادة محاولة بتراجع أسّي | نقطة استقبال متعطّلة لا يجوز أن تُفقد حدثاً |
| طابور وعامل | الإرسال المتزامن مع الطلب يجعل بطء المستقبِل بطءَ مرصد |
| سجلّ تسليم | «هل وصل الحدث؟» سؤالٌ يجب أن يُجاب |

<Callout type="info" title="ولماذا لا يُبنى المختصَر منها">
إرسال `POST` بلا توقيع ولا إعادة محاولة ولا سجلّ **يبدو** webhook ويتصرّف
كخسارة صامتة للأحداث. وغيابه أصدق من وجوده ناقصاً.
</Callout>
